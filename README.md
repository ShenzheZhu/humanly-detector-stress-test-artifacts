# Humanly Detector Stress-Test Artifacts

This repository contains the de-identified artifacts for the final-text-only detector stress test reported in the Humanly demo paper.

## Contents

- `data/samples.jsonl`: canonical detector-facing final texts, one JSON object per sample.
- `data/sample_manifest.csv`: sample IDs, case labels, length buckets, word counts, and source notes without full text.
- `data/cases.csv`: the eight construction cases and their expected document classes.
- `data/source_families.csv`: source families used to construct the dataset.
- `data/overall_metrics.csv`: aggregate predictor results.
- `data/case_metrics.csv`: case-level predictor results.
- `raw/gptzero/`: raw GPTZero API responses for all 240 samples.
- `raw/pangram/`: raw Pangram API responses for all 240 samples.
- `raw/opus_4_8/`: raw LLM-as-predictor responses for all 240 samples.
- `source_seeds/non_english_project_gutenberg/`: retained legacy non-English seed snippets from an earlier C3 fallback path. The released C3 detector-facing samples are the canonical final texts in `data/samples.jsonl`; their source families are summarized in `data/source_families.csv`.

The raw Prolific exports used for human editing and human AI-style writing are not included because they may contain participant identifiers. Only the de-identified final texts and aggregate metadata are included here.

## Rebuild

Run:

```bash
node scripts/build_artifact.mjs
```

The script rebuilds `data/samples.jsonl`, `data/sample_manifest.csv`, `data/cases.csv`, `data/source_families.csv`, `data/overall_metrics.csv`, and `data/case_metrics.csv` from the raw detector outputs and the case definitions encoded in the script. It also verifies that GPTZero and Pangram were run on identical final text for each sample.

## Labels

The document class labels are:

- `HUMAN_ONLY`: the final text is human-authored without in-text AI rewriting.
- `MIXED`: the final text combines human writing with allowed AI transformation or editing.
- `AI_ONLY`: the final text is substantively generated by AI.

The benchmark policy treats C1-C4 as compliant and N1-N4 as non-compliant.
